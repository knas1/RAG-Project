# روبوت المعايير (Standards RAG Chatbot)

نظام أسئلة وأجوبة على ملفات معايير بصيغة PDF، مع اقتباسات موثّقة (المعيار + الإصدار + رقم البند + الصفحة). **لا يوجد "تدريب" للنموذج** — تفهرس ملفاتك مرة واحدة ثم تسأل.

يعمل بوضعين:
- **بدون LLM** (`search.py`): يعيد لك أقرب البنود من المعايير — تقرأها بنفسك.
- **مع LLM** (`chatbot.py`): يصوغ إجابة بلغة طبيعية مع اقتباسات — سحابي أو محلي.

---

## 1) المتطلبات

- Python 3.10 أو أحدث.
- إنترنت **مرة واحدة فقط** لتحميل الحزم والنماذج. بعدها يمكن العمل أوفلاين بالكامل (مع الوضع المحلي).

تحقّق من إصدار Python:
```bash
python3 --version
```

---

## 2) التثبيت

من داخل مجلد المشروع:
```bash
pip install -r requirements.txt
```
أول تشغيل سيحمّل نموذج الـ embedding ونموذج إعادة الترتيب (بضع مئات الميغابايت). هذا يحدث مرة واحدة.

## تشغيل على Google Colab

في Colab، ضع علامة `!` قبل أوامر الطرفية، و`%env` لمتغيّرات البيئة:

```
!pip install -r requirements.txt
```
ارفع ملفات PDF إلى مجلد `pdfs` (من الشريط الجانبي: Files → اسحب الملفات داخل `pdfs`)، ثم:
```
!python ingest.py --reset
!python search.py "minimum password length"
```
للوضع مع LLM سحابي:
```
%env OPENAI_API_KEY=sk-...
!python chatbot.py "minimum password length"
```

**تنبيه مهم:** تخزين Colab **مؤقّت** — عند إغلاق الجلسة تختفي مجلدات `pdfs` و`chroma_db`. لحفظها بين الجلسات، اربط Google Drive وخزّن قاعدة البيانات هناك، أو أعد رفع الملفات وبناء الفهرس في كل جلسة.

**ملاحظة عن الوضع المحلي (Ollama):** غير عملي على Colab عادةً — استخدم الوضع السحابي على Colab، والوضع المحلي على جهازك.

## 3) وضع ملفات المعايير

أنشئ مجلد `pdfs` وضع ملفاتك فيه:
```bash
mkdir pdfs
# ثم انسخ ملفات PDF إلى داخل المجلد
```

**مهم:** إذا كانت ملفاتك **ممسوحة ضوئيًا (صور)** فلن يُستخرج منها نص. للتأكد: افتح الملف وحاول تحديد النص بالماوس. إن لم تستطع، تحتاج OCR أولًا (مثلًا أداة `ocrmypdf`).

### (موصى به) تعريف اسم وإصدار كل معيار
افتح `config.py` وعدّل `MANIFEST` ليطابق أسماء ملفاتك:
```python
MANIFEST = {
    "ISO-9001-2015.pdf": {"standard": "ISO 9001", "version": "2015"},
    "IEC-62304-2006.pdf": {"standard": "IEC 62304", "version": "2006"},
}
```
لو تركته فارغًا سيستخدم اسم الملف — يعمل، لكن الاقتباسات تكون أقل وضوحًا، ولن تستطيع الفلترة حسب الإصدار بدقة.

---

## 4) بناء الفهرس (خطوة إلزامية لكلا الوضعين)

```bash
python ingest.py --reset
```
هذا يقرأ كل ملفات PDF، يقسّمها حسب البنود، يحسب الـ embeddings، ويخزّنها في قاعدة `chroma_db`.

- استخدم `--reset` لبناء الفهرس من الصفر.
- عند إضافة/تعديل ملف لاحقًا، شغّل `python ingest.py` بدون `--reset` (يضيف الجديد فقط).

إذا ظهرت رسالة "no text extracted" لأحد الملفات، فهو ملف ممسوح ضوئيًا ويحتاج OCR.

---

## 5) الوضع الأول: بدون LLM (بحث فقط)

لا يحتاج أي مفتاح ولا إنترنت. يعيد لك أقرب المقاطع من المعايير.

```bash
python search.py
```
ثم اكتب سؤالك. أو مباشرة:
```bash
python search.py "minimum password length firewall"
```
للفلترة على معيار واحد:
```bash
python search.py --standard "ISO 9001" "password length"
```

**ماذا تتوقّع:** يعرض لك فقرات البنود كاملة مع مصدرها ودرجة الصلة. لن يستخرج الرقم المحدد ولن يصوغ جوابًا — تقرأ الفقرة بنفسك.

**ملاحظة عن الأخطاء الإملائية:** البحث الدلالي يفهم المعنى، لذا سؤال مكتوب بعجالة أو فيه خطأ بسيط ("menium" بدل "minimum") غالبًا يسترجع البند الصحيح، لأن بقية الكلمات دالّة. لكن إن كان الخطأ في المصطلح الحاسم الوحيد، قد تقلّ الدقة.

---

## 6) الوضع الثاني: مع LLM (إجابة مصاغة + اقتباسات)

### 6أ) LLM سحابي (الأسرع للتجربة)

```bash
export OPENAI_API_KEY=sk-...
python chatbot.py
```
لا تعديل على الكود. الإعداد الافتراضي `gpt-4o-mini`.
تنبيه خصوصية: مقاطع من معاييرك تُرسَل إلى مزوّد السحابة. عبر واجهة الـ API لا يُدرَّب عليها افتراضيًا، لكنها تخرج من جهازك.

### 6ب) LLM محلي عبر Ollama (أوفلاين + خصوصية كاملة)

1. ثبّت Ollama من موقعه الرسمي، ثم حمّل نموذجًا (يحتاج إنترنت مرة واحدة):
```bash
ollama pull qwen2.5:14b
```
2. عرّف المتغيرات:
```bash
export OPENAI_API_KEY=ollama
export OPENAI_BASE_URL=http://localhost:11434/v1
```
3. عدّل سطرًا واحدًا في `config.py`:
```python
LLM_MODEL = "qwen2.5:14b"
```
4. شغّل:
```bash
python chatbot.py
```
لا تعديل آخر — الكود متوافق مع واجهة OpenAI فيعمل مع Ollama مباشرة.

> اختيار النموذج حسب جهازك: كرت شاشة بذاكرة 24GB → `qwen2.5:14b` أو أكبر. ذاكرة أصغر (8–12GB) → `llama3.1:8b`. CPU فقط → يعمل لكن بطيء، والدقة أقل على الأرقام الدقيقة.

## 7) الفرق بين الوضعين

| | بدون LLM (`search.py`) | مع LLM (`chatbot.py`) |
|---|---|---|
| فهم السؤال المصاغ بشكل سيئ | جيد (بحث دلالي) | جيد (نفس البحث الدلالي) |
| يصوغ إجابة بلغة طبيعية | لا | نعم |
| يستخرج الرقم/القيمة المحدّدة | لا (تقرأ الفقرة) | نعم |
| يرفض التخمين عند غياب الجواب | لا | نعم (`INSUFFICIENT_CONTEXT`) |
| يوحّد إجابات من عدة بنود | لا | نعم |
| يحتاج مفتاح/نموذج | لا | نعم |
| السرعة | الأسرع | أبطأ (خاصة المحلي على CPU) |

الخلاصة: للحصول على "رقم دقيق مستخرج" (مثل الحد الأدنى لطول كلمة المرور) تحتاج الوضع مع LLM. البحث وحده يعطيك الفقرة لتقرأها.

## 8) الضبط والتحسين

كل المفاتيح في `config.py`:

- `RERANK_MIN_SCORE` (بين 0 و 1): أهم مِقبض للدقة. ابدأ بـ 0.30 واضبطه على أسئلة حقيقية. عالٍ جدًا → يُسقط بنودًا صحيحة. منخفض جدًا → يُدخل ضوضاء.
- `RERANK_TOP_N`: عدد المقاطع النهائية (افتراضي 6).
- `RERANK_MODEL`: لدقة أعلى (وبطء أكثر) استخدم `BAAI/bge-reranker-v2-m3`.
- `USE_LLM_GRADER = True`: فلتر صلة إضافي قبل التوليد (يزيد الدقة ويزيد البطء/التكلفة). يعمل فقط في وضع LLM.
- `MAX_CHUNK_CHARS` / `CHUNK_OVERLAP_CHARS`: حجم التقسيم. عدّلهما ثم أعد `python ingest.py --reset`.

---

## 9) تحديث المعايير لاحقًا

- **معيار جديد:** ضع الـ PDF في `pdfs/`، عرّفه في `MANIFEST`، ثم `python ingest.py`.
- **إصدار منقّح:** أعطِ الملف الجديد اسمًا مختلفًا وإصدارًا مختلفًا في `MANIFEST` (يبقى الإصداران قابلين للبحث)، ثم `python ingest.py`. أو `python ingest.py --reset` لإعادة بناء كل شيء.
- **حذف معيار:** احذف الملف ثم `python ingest.py --reset`.

لا يوجد "إعادة تدريب" في أي حالة — فقط إعادة فهرسة، وهي سريعة.

---

## 10) مشاكل شائعة

- **"No PDFs found":** لم تضع ملفات في مجلد `pdfs/` أو المسار خاطئ في `config.py`.
- **"no text extracted":** الملف ممسوح ضوئيًا (صورة). طبّق OCR أولًا.
- **إجابات ضعيفة/ناقصة:** جرّب خفض `RERANK_MIN_SCORE` قليلًا، أو رفع `RERANK_TOP_N`، أو نموذج reranker الأقوى.
- **بطء في وضع LLM المحلي:** طبيعي على CPU. استخدم نموذجًا أصغر أو جهازًا بكرت شاشة.
- **بطء عند الإقلاع:** فهرس BM25 يُبنى في كل تشغيل من قاعدة البيانات. سريع للمجموعات الصغيرة/المتوسطة.

## ملاحظة صدق مهمة

هذا الكود **مفحوص صياغيًا** (كل الملفات تُصرّف بنجاح)، لكنه **لم يُشغّل من البداية للنهاية على بيانات حقيقية** في بيئة إعداده (لا إنترنت ولا تحميل نماذج هناك). قبل الاعتماد عليه:
1. شغّله على ملف PDF واحد أولًا.
2. اسأل 5–10 أسئلة تعرف إجاباتها.
3. تحقّق أن الاقتباسات تشير إلى البند الصحيح فعلًا.
